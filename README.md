# Tooku

面向中文用户的 Navidrome 第三方网页播放器。目标是让自己的音乐库更好找、更好听、更好看。

Tooku 的产品边界是一个可自行部署的轻量网页客户端：Navidrome 继续负责音乐库、扫描、收藏、歌单和转码；Tooku 只负责浏览与播放体验、会话安全代理，以及少量界面偏好和备份。Node 与 SQLite 和前端同进程运行，不引入微服务、任务队列、云端账号或常驻抓取任务。网络歌词和音乐推荐保留为用户主动使用的可选能力，后续只维护稳定性，不继续扩展平台、模型或后台服务。

Tooku 取自日语「遠く」。[SVG 标志](public/tooku.svg) 以落日、远山和湖面右侧的音波表达距离与回响，不包含文字；登录页、主界面和站点图标共用这份彩色矢量素材。桌面登录页中，尺寸相近的 Navidrome 官方图标起初藏在 Tooku 标志后方，悬停后旋转滑出，说明第三方播放器与服务端的关系；登录页固定使用亮色，以「让音乐，陪你去远方」及「Navidrome 第三方音乐播放器」明确产品定位，登录后恢复用户选择的明暗主题。

状态更新：2026-10-23。**可运行的开发工程，真实曲库已进行基础联调，尚未完成发布验收**。保留 Apple Music 的简洁视觉，主界面现采用 Spotify 式全局头部与三栏布局，明暗模式与主题色可选。本地 Git 已提交基线，本轮功能在 codex/library-workspace 分支；没有远程推送。

**Agent / 开发者接入：先读 [AGENTS.md](AGENTS.md)，再按任务查阅 [开发接入指南](docs/12-agent-development-guide.md)。** 两者说明当前模块入口、产品交互、数据边界与验证方式；早期设计文档包含已被替代的方案。

## 本地运行

需要 Node.js 24.22.1+（内置 SQLite 与 TypeScript 执行），项目通过 `engines`、`.nvmrc`、启动/构建/测试入口和 Docker 镜像统一执行最低版本检查；较旧运行时会在加载应用前停止并显示当前版本。**无需安装全局 pnpm**：已有依赖时可双击根目录 [start-tooku.cmd](start-tooku.cmd)，或通过 npm 启动。

```powershell
Set-Location G:\Code\Tooku
npm.cmd run dev
```

终端需保持运行，按 Ctrl+C 停止后地址将无法访问。电脑重启后双击启动脚本，脚本会启动服务并自动打开浏览器；需保持窗口打开。重复启动会打开已经运行的 Tooku。如果首次下载项目、尚无 node_modules，脚本会使用 `npx.cmd --yes pnpm@11.25.0 install --frozen-lockfile` 安装锁定依赖，不依赖系统 PATH 中的 pnpm。

默认打开 `http://127.0.0.1:18733/`；端口被占用或被 Windows 保留时，启动器会在 18733–18742 中尝试其他端口，实际地址显示在终端并写入本机 `.local/server-url.txt`。旧端口 5173 在本机 Windows 保留范围内，会报 EACCES，因此已更换。可通过进程环境变量 `TOOKU_PORT` 指定首选端口，无需更改系统网络设置。

手机与电脑在同一局域网时，先在原启动窗口按 Ctrl+C 正常停止 Tooku，再运行 `npm.cmd run dev:lan`（或 `./start-tooku.cmd --lan`）。该模式监听 `0.0.0.0`，终端列出各网卡的 `LAN` 地址；手机打开电脑 Wi-Fi 网卡对应的地址，不能使用手机自身的 `127.0.0.1`。已运行的仅本机服务不会自动切换监听范围、被终止或另启一份，启动器会提示先重启；普通启动仍默认仅本机。局域网模式用于可信网络内调试，保持现有主机校验，不开放任意域名；若改为局域网监听后仍无法连接，再检查 Windows 防火墙对该 Node 进程/实际端口的入站放行。手机登录时服务器地址使用当前 Tooku 站点根地址，可自动走电脑上的 `/api/navidrome` 固定上游代理；不要填写手机自身的 `127.0.0.1:44533`。

局域网 HTTP 下播放器、队列和文件夹的 UUID 由 `src/domain/ids.ts` 统一生成：优先原生 `crypto.randomUUID()`，缺少该接口时以 `crypto.getRandomValues()` 生成同格式 UUID，避免模块初始化白屏。Windows 防火墙需按当前网络类别匹配规则；“公用网络”下的 Node 放行不适用于“专用网络”。需要放行时只开放实际 Tooku TCP 端口、本地子网和所用 Node 程序，不关闭防火墙。

登录页首次服务器地址留空；成功登录后仅在此浏览器记住该服务器地址，返回或刷新登录页自动回填，测试连接或失败尝试不覆盖它；不记住用户名、密码或带认证信息的 URL。填写完整 HTTP(S) 地址。「测试连接」使用不带账号和密码的音乐服务 ping，显示可达状态及本次 API 往返耗时，不验证账号、不登录或启动数据恢复。检测有 8 秒超时，修改地址或离开页面会取消旧请求。输入框无边框，聚焦以底色变化提示；登录页的背景、控件焦点和文本选中固定使用亮色中性色，不受用户主题配色影响。

填写当前 Tooku 站点地址、部署配置的默认 Navidrome 地址（本机默认 `http://127.0.0.1:44533`），或服务端可达的其他完整 Navidrome HTTP(S) 地址，都会通过正式 `/api/navidrome` 受管代理建立服务器账号会话；直接填写旧地址时继续使用原浏览器数据身份，因此已有本地数据不会丢失。旧 `/nd` 输入继续兼容。其他地址会先由服务端验证，公网地址默认可登记，私网/回环地址需部署者显式开启。服务器地址只在登录页选择，设置中不提供服务器记录或地址别名管理；需要更换入口时退出后使用新地址登录。使用你自己的 Navidrome 用户名和密码；密码不保存。受管上游的目标与认证材料在 Tooku 后端加密存储，浏览器使用 HttpOnly 会话 Cookie，30 天内刷新或重开可自动登录，退出会撤销当前设备会话；队列以暂停状态恢复。

「进入音乐库」按钮固定为黑色。连接、数据恢复及播放器接入成功后，登录内容渐隐，左上角标志和文字平滑过渡到工作区位置；开启减少动态效果、页面在后台或浏览器不支持时直接切换，动画失败不影响登录。

Tooku 前端与同一 Node 服务通过轻量协议版本核对；出现“前后端版本不兼容”时先强制刷新页面，仍存在则升级并重启 Tooku，不能只替换静态文件。浏览器拒绝 localStorage 或 IndexedDB 时应用会退回本次页面内存并明确提示：服务器账号数据仍可使用，但设备显示偏好、队列、历史或离线副本可能无法在刷新后恢复；损坏的本地设置 JSON 会被单项忽略，不清除服务器数据。

生产构建提供轻量 PWA 应用壳，可由支持的浏览器安装。Service Worker 只预缓存当前版本的 JS/CSS 与品牌图片，离线时可打开登录外壳并明确提示 Navidrome 不可用；音乐、封面、歌词、API、认证与账号数据均不进入应用缓存。检测到新版本后由用户选择“更新并刷新”，不会在播放中自动接管。应用缓存可在「账户与设置 → 用户数据 → 高级设置」单独清除，不影响登录、队列或服务器备份。远程安装需要 HTTPS，本机 localhost 可直接测试；具体安装入口和图标呈现取决于浏览器与系统。

服务器连接与账号密码使用独立表单；地址关闭自动补全并提供 Bitwarden 忽略提示，账号字段使用稳定的 `username` / `password` 标识及标准自动填写语义。提交读取输入框的实际值，兼容未触发 React 更新的密码管理器填写；输入法确认不会触发提交，地址错误会聚焦对应输入框。具体密码管理器扩展仍需实际验证。

npm.cmd run typecheck
npm.cmd test

现已实现：登录和扩展检测、专辑完整列表浏览、歌手横幅详情与播放、中文输入法安全的检索、收藏、普通歌单与保存核实、常驻播放器、队列与循环/随机、本地/网络双语歌词与偏移、浏览器全屏与桌面画中画歌词、Last.fm / AI 推荐及四平台外链、Media Session、账号数据同步/备份恢复、本机快照/收听历史、响应式与主题设置。**实现不代表所有 Navidrome 音频格式、权限和扩展都已实测。**

受管上游账号播放时，播放器先向 Tooku 申请只绑定当前 HttpOnly 会话、账号、歌曲和原始/兼容模式的随机临时地址，再由服务端向会话绑定的 Navidrome 注入认证；通用 `/api/navidrome/rest/stream` 与 download 入口已关闭。授权最长四小时，同一会话开始新曲、重新登录或退出会撤销旧授权；允许单段 Range、seek 和最多三路短时并发，拒绝多 Range 与异常重放。响应固定为 inline、private/no-store、同源策略，并将上游音频 MIME 统一掩码为 `application/octet-stream`，同时保留原字节、长度与 Range/Content-Range，减少扩展仅按响应类型识别音乐流；参考 Nginx 模板关闭授权路径访问日志。暂停到临近过期后恢复会先换取新地址，不把授权写入队列、历史或备份。未通过服务端策略或协议验证的地址仍回退浏览器直连，并受 CORS 与本地存储边界限制。此措施用于降低下载器扩展自动接管和批量抓取，不是 DRM，也不能阻止已授权用户录制或保存可播放内容。

当前功能、收敛后的开发计划、最近检查及未测边界统一见 [开发记录](docs/09-development-status.md)。真实部署与长时播放仍按具备环境时补验；拼音搜索和只有睡眠定时的操作工具已按当前计划跳过。同浏览器并行多服务器、实时跨设备控制、智能歌单引擎、离线音乐和音频 DSP 不再作为近期计划；推荐与外部平台不继续扩张。

专辑列表自动按每批最多 500 张读取，全部完成后统一显示，封面仍延迟加载；随机发现先完整读取再打乱，避免随机分页遗漏。专辑和歌手列表可选每行 3/4/5/6/8 个，分别记住本机选择；窄内容区自动减少列数时，控件显示当前实际列数并禁用无效选项，较宽布局的原偏好继续保留。歌手详情的专辑区复用专辑列数。专辑、歌手和歌单详情统一播放/随机按钮。底栏歌曲名按本次播放来源进入专辑或歌单，并定位到对应歌曲，不添加定位边框；来源不明时以专辑兜底，跳转不中断播放。

手机界面采用单行导航/主页/搜索/头像，主页与搜索成组并留出两侧间距；专辑和歌手固定两列并隐藏列数菜单。底栏只显示封面、歌曲/歌手、收藏、队列和播放/暂停，收藏位于队列左侧；在封面与歌曲信息区域左滑播放下一首、右滑播放上一首，拖动时当前封面和元信息向边缘移动并渐隐，相邻歌曲的真实封面、曲名和歌手从另一侧渐显进入，确认后补完到中间并调用与桌面按钮相同的播放器命令，同时抑制滑动后的误点。长歌曲名和歌手名单行往返滚动，保留点击跳转，减少动态效果时仍可手动横向查看。队列从底部以约四分之三屏展开，可拖动手柄向上全屏，也可点击手柄切换；播放按钮不加圆形背景，关闭直接返回浏览页，不显示桌面右侧栏。桌面列数与侧栏偏好保留。

手机展开播放器以完整封面与播放控制作为首屏，左滑进入歌词，右滑返回，兼容鼠标拖动和键盘左右键。横向拖动和 160 ms 松手过渡统一移动同一条轨道，松手优先使用浏览器原生 transform 动画、旧 WebView 保留兼容回退，不再与浏览器横向滚动/吸附混用；限制边缘越界，支持短距离快速轻扫，新手势可从正在移动的位置接续。浏览器地址栏引发的高度变化不重置切页。歌词仍可上下独立滚动，进度条与长文字操作保留；歌名/歌手的滚动区域兼容隐藏双向滚动条，只允许横向查看；不放底部提示或歌词页返回按钮，下滑收起已取消，使用右上角收起或 Escape 回到主界面。切页保留同一歌词组件和播放进度，桌面仍为左右布局。

系统媒体控制通过 Media Session 接收当前歌曲的歌名、歌手、专辑和封面；封面地址仅保留在当前会话，不进入队列备份。切换无封面歌曲、清空队列或退出时清理旧封面。系统卡片的实际呈现仍取决于浏览器和系统支持。

触摸图标时只有长按才显示操作提示，松开、滑动或切页即隐藏；鼠标悬停与键盘导航仍可显示。键盘导航保留焦点提示，系统音量和媒体键不让鼠标或触摸选中的控件突然出现焦点框。已防护原生浮层在关闭/切页期间的状态异常，其他渲染错误会显示“恢复界面”入口，恢复时保留会话、查询缓存与音频单例；这不代表已覆盖所有偶发白屏原因。

从头像进入「账户与设置」，按账户与音乐库、外观、播放与操作、网络歌词、音乐推荐、用户数据六类浏览。窄内容区使用顶部分类；切换分类保留未保存的推荐配置与检测结果，播放侧栏布局集中在播放分类，账号保存状态、统一备份恢复与本机快照集中在用户数据，只有数据冲突时才展开版本选择。

主页统一从「全部」开始，不再设置默认浏览入口。外观将默认色、模板和自定义统一在下拉菜单，选项带色块，使用红/蓝/紫/绿/橙的普通名称，自定义色块与色值共用输入框；字体可选思源黑体、思源宋体、系统黑体和系统宋体，两款思源字体按 OFL 1.1 随项目提供，系统字体不随包分发。字体和 13/14/16/18 px 基础字号仅保存在此浏览器，歌词字号独立。歌词和推荐服务均显示状态灯；推荐设置中的 Last.fm / AI 默认展开，Apple Music / Spotify 默认折叠，地区使用少量常用代码（Apple 小写、Spotify 大写），下拉菜单跟随页面滚动。保存按钮位于表单末尾；「新歌手目标占比」以本次收听样本为参照。

受管上游账号数据现在以 Tooku 服务器数据库为主，浏览器保留离线缓存与未保存修改。用户数据页提供统一的导出备份、从文件恢复和旧版本恢复；只有迁移冲突、409 或未知写入核实后才比较版本。恢复保留原数据副本，当前播放继续，恢复的队列和历史保护到下次登录。未通过后端策略或验证的直连模式也支持本地备份和恢复。

左栏“最近在听”下方为“为你推荐”，主页“全部”提供简洁的文字入口板块，不展示歌曲明细。使用最近 30–50 首不同歌曲，手动生成 10 / 20 / 30 首（默认 30），推荐页与设置均可调整数量。Last.fm 平衡全部提交样本，候选不足时延伸探索；AI / 混合模式可提名经目录核实的新歌，略过或筛选后不足时按缺额最多追加两轮，达到目标即停止；上游持续失败时保留真实结果并说明缺额。同歌手、已知同名专辑最多一首，避开最近推荐过的 300 个 ID，并比较近期 90 首的歌名/歌手及已知录音室版本标记，减少跨平台重复；现场、翻唱、混音与未知版本保持区分。推荐页只保留一个主标题和一行批次信息，采用与歌单一致的文字列表，歌名、歌手分列，显示专辑、可信发行日期和时长，缺失为“—”，不放封面占位图。进入推荐页即分组核实整批网易云、QQ、Apple Music、Spotify 链接；点击歌曲打开平台菜单，未完成时显示核实提示；失败直接使用搜索入口，不增加重试操作，不播放、不下载图片。目录查询与 Spotify 临时令牌在服务内存中受限复用，减少生成后重复查链接；Last.fm 明确认证失败或限流时停止后续查询，AI 仍可独立继续。展开“收听参考”可查看将提交的样本；结果标明实际使用的算法/AI/混合模式。普通设置、最近结果及有限避重元数据按账号保存，服务密钥可按账号加密保存在 Tooku 后端，刷新或重新登录后仍可使用；推荐质量仍需实际收听判断。详见 [音乐推荐](docs/16-music-recommendations.md)。

推荐设置的检测结果直接显示在各服务按钮旁。Last.fm 使用 API key，无需 Shared secret；DeepSeek 建议填写 `https://api.deepseek.com/v1`，旧根地址统一使用同一接口。检测和生成共用非思考 JSON 模式、Node 默认与系统已信任 CA，保持严格 TLS 校验；成功会明确显示 JSON 输出正常，空内容、截断、认证、余额、网络等故障分别提示。修改系统证书信任后需正常重启 Tooku。

底部播放栏新增“桌面歌词”按钮，通过文档画中画打开置顶小窗，逐句显示原文与已有译文，跟随切歌、歌词来源、显示设置与同步偏移；没有时间轴的歌词可手动滚动。浮窗沿用应用主题，可拖动和缩放，关闭不影响音乐。需浏览器支持 Document Picture-in-Picture（如新版桌面 Chrome / Edge），远程部署需 HTTPS，本机 `127.0.0.1` 可用；不支持或打开失败会提示。初始请求 480 × 180，位置由浏览器决定，通常位于右下角，后续沿用浏览器记住的位置与大小，网页无法强制指定坐标。刷新、退出登录或关闭主页面会关闭浮窗，不自动重开。

展开播放器使用柔化封面背景，左侧封面与播放控制固定，超长歌曲名和歌手名在固定单行区域内往返滚动，悬停或聚焦暂停、减少动态效果时手动查看；封面、列间距与歌词字号随可用宽高缩放，适配 1K / 2K / 4K 和浏览器缩放；右侧大字歌词限制阅读区高度，当前句位于中部略上，右上角收起。收藏旁三点菜单提供查看专辑、歌手、当前来源歌单和添加到歌单；无歌单来源时禁用查看歌单。底栏收藏紧邻歌曲名与歌手名，随文字宽度移动。展开界面不放音量、底部歌词设置、队列切换和装饰小字。手动浏览歌词时显示“同步”，闲置 5 秒后自动跟随当前行并收起按钮。随机播放后，在相同专辑、歌单或来源列表内点歌会保留随机模式；切换其他来源默认顺序播放。来源、随机模式与关闭随机时的原始顺序随队列保存，旧快照仍可读取；旧队列没有来源信息时，从歌单重新点播即可记录。

新版主页展示曲库概览，支持全部、歌单、专辑、歌手筛选，歌手卡片可进入详情；底部不放曲库名与“浏览所有歌曲”小字。Logo/后退/前进/主页/搜索位于头部，账户设置只从头像菜单进入，菜单也可快速切换真实曲库。专辑列表完整读取后统一显示，保留排序与失败重试；歌手详情统一为柔化背景与方形前景图片，管理员可悬停/聚焦图片后更换并裁剪，保存到 Navidrome，其他客户端可读取；右键可恢复服务器默认图片。原有 Tooku 私人图片保留，不自动上传覆盖服务器图片。默认依次使用 Navidrome 歌手图、本库专辑封面、主题渐变。播放与专辑区域使用纯色背景，全部页面、左侧歌单与右侧播放栏提供贴边的 8 px 半透明浮动滚动条，悬停变亮、无上下箭头；弹窗与菜单使用统一透明轨道样式。右栏支持调整宽度、版块与顺序，完整队列在栏内覆盖显示，关闭后恢复原侧栏及滚动位置，不再使用顶部视图切换；左栏歌单树独立管理，文件夹默认展开，展开/折叠状态按账号保存到浏览器，固定上游登录时同步到 Tooku 数据库。歌曲表格支持列宽调整、空白区域双击播放和统一右键操作；歌单与文件夹在左栏拖动排序，使用横线落点与精简名称预览，主体管理页仅浏览；歌单内歌曲拖动后直接保存，不显示成功提示或撤销按钮，失败时可重新读取核实；封面点击直接选图裁剪，名称和简介从三点菜单编辑，编辑弹窗的封面与右侧表单上下对齐。长歌单时长仅显示约整小时。主体卡片和左栏文件夹不放三点图标，保留右键管理；新建歌单无位置小字，根目录统一为 `/`。无编辑权限时显示锁与只读提示，服务器管理的曲目显示“自动维护歌单”，悬停或聚焦提示修改原 m3u/m3u8 文件后重新扫描。

**Tooku 现有 Node.js + SQLite 用户数据后端。** 登录部署配置的固定上游或服务端验证通过的其他 Navidrome 地址后，自动保存头像、歌单封面、旧版私人歌手图片、目录、偏好、队列和历史；当前站点、默认 `44533` 地址和旧 `/nd` 都属于同一服务端账号。服务器为空时自动上传当前地址身份下的原浏览器数据；新浏览器本地没有个性数据时自动读取服务器，无需手动确认迁移。已有浏览器数据保留，只有两端都有不同个性数据或待核实的保存结果时，才从头像 → 账户与设置 → 用户数据预览选择版本。已连接设备在下次登录读取新版本，不实时接管另一设备的播放。其他地址先由服务端匿名验证并取得十分钟连接票据，登录后代理目标固定在加密会话中；默认允许公网 HTTP(S)，私网/回环地址需配置 `TOOKU_ALLOW_PRIVATE_NAVIDROME=true`，固定上游不受此开关影响。名称、简介、歌曲和曲序等歌单数据继续保存在 Navidrome；新上传的歌手图片也直接由 Navidrome 保存，不占 Tooku 账号文档。图片编辑需原生 API 管理员会话，更新后请重新登录；原生认证失败不影响听歌。

默认账号数据库 `.local/data/tooku.sqlite`，凭据独立保存在同目录 `tooku-security.sqlite`，加密密钥为 `tooku-secret.key`（可用 `TOOKU_SECRET_KEY_FILE` 指向独立挂载）。账号备份不含登录或服务密钥；迁移整个部署需额外保留安全库与原密钥，丢失密钥不能自动重建解密。生产 HTTPS 可配置 `TOOKU_COOKIE_SECURE=true`，或在可信反向代理后配置 `TOOKU_TRUST_PROXY=true` 并转发单值 `X-Forwarded-Proto`；只有最终入口确认全站 HTTPS 后才同时设置 `TOOKU_HSTS=true`，服务会在可信 HTTPS 请求上发送一年 HSTS。不要在可由客户端直连的 Node 端口启用代理信任。生产响应统一带 CSP、`frame-ancestors 'none'`、Permissions-Policy、拒绝嵌入与 MIME 嗅探策略；CSP 保留任意已配置 HTTP(S) Navidrome 的 API、封面和音频访问。可用进程环境变量 `TOOKU_DATA_DIR` 指定持久化目录；不要放在构建输出目录。生产运行先执行 `npm.cmd run build`，再执行 `npm.cmd start`，默认监听 `127.0.0.1:18733`；可用 `TOOKU_HOST` / `TOOKU_PORT` 调整。生产运行不依赖 node_modules；`npm.cmd run preview` 仅预览静态资源，不能替代 Node 服务。设置中可导出/恢复当前账号 JSON，管理员可用 `npm.cmd run backup -- .local/backups/tooku.sqlite` 创建新的账号数据库备份（不包含凭据安全库）。恢复步骤、代理和数据边界见 [服务端持久化](docs/13-server-persistence.md)。

## 可选 Docker 部署

已准备 [Dockerfile](Dockerfile) 和 [Compose](compose.yaml)，使用 Node.js 同时提供静态页面、用户数据/歌词/推荐 API 和固定上游代理。基础镜像固定为 Node 24.22.1 Alpine 的官方多架构 digest；运行层删除 npm/corepack 并由 Node 直接启动，内置应用健康检查。Compose 使用明确的非 root UID/GID、只读根文件系统、受限 `/tmp`、无 Linux capabilities、no-new-privileges 及 PID/内存/CPU 限制，默认只映射到本机。账号数据库和安全库存入 `tooku-data`，主密钥单独存入 `tooku-security-key`。完整配置、同网络/远程 HTTPS 上游、备份、代理、升级与回滚步骤见 [容器部署](deploy/README.md)。此电脑没有 Docker/Podman/nerdctl/buildah，真实构建、运行、卷恢复和最终镜像扫描仍需在 Docker 主机验收。

```powershell
docker compose up --build -d
```

配置通过 `http://127.0.0.1:8080/` 提供 Tooku，`NAVIDROME_UPSTREAM` 默认指向宿主机 44533；容器中的 localhost 是容器自身。若 Navidrome 位于其他容器/设备或子路径，通过环境变量或 [同网络叠加配置](deploy/compose.same-network.yaml) 指定上游（不要带尾斜杠）。Linux 上服务只绑定 127.0.0.1 时，host-gateway 并不保证能连接，应选择同一容器网络或宿主机实际可达地址。远程访问需配置 HTTPS 入口。

## 推荐路线

当前为 React + TypeScript + Vite 网页应用及单进程 Node.js / SQLite 配套层，以 Subsonic / OpenSubsonic 为音乐数据协议，使用常驻 HTMLAudioElement 播放。账号持久化、歌词和推荐模块都在同一进程内按请求工作，不是独立常驻服务。迁移与备份恢复、歌单权限和保存核实已有实现；真实权限矩阵、长期播放、性能和部署仍待发布前验证。轻量 PWA 应用壳已经接入；拼音搜索和单独睡眠定时已跳过，歌词增强保持低优先级，高级音频不在近期计划。

网络与双语歌词见 [独立歌词组件方案与实现](docs/15-lyrics-service-design.md)：组件随 Tooku 同端口启动，脱离 Navidrome 的网络查询与检测，支持网易云 / QQ 音乐；默认本地优先，明确缺失才联网。展开页顶部来源、歌词设置、全屏与收起图标同行，去掉胶囊外框并以竖线分组，QQ 使用企鹅图标；底栏最右按钮直接打开浏览器全屏播放器，退出全屏不改变音频。展开页右键复用当前歌曲更多选项；来源只有本地、网易云和 QQ，缺本地时自动采用网络相近版本；歌手匹配兼容多人合写、括号与平台别名，支持原文加括号译名的歌名，以及平台确认的中文/日文歌手名关联。网易云组合检索失败时受限回退为仅歌名检索，再按歌手/时长筛选；QQ 优先使用新版匿名明文接口显式请求译文，故障可回退旧接口，空译文时保留原文。“歌词设置”将显示、双语排版、同步偏移和版本搜索合并到一个面板；显示页使用“自动识别”双语格式，重置与刷新同行、保存独占一行，不放预览；内部滚动为输入框焦点边框留白，版本页先填歌曲标题和歌手，再选择平台并搜索，不放刷新按钮；纯音乐或最终无结果统一显示“该音乐没有歌词，请欣赏”。设置中的“网络歌词”可调整来源顺序、查看真实运行状态并检测。个人选择随账号备份，公开歌词放独立缓存，不写回标签。未知排版保留原文，可手动指定；不生成译文或时间戳。平台匿名接口可能变化，本次公开样本通过不代表全部歌曲可用。既有服务未加载新接口时，在停止播放后正常重启 Tooku 即可。

核心差异化：中文输入与检索体验、精致且可降级的歌词页、明确可控的播放队列、稳定的连续听歌流程。首页内容来自用户自己的音乐库。
