### 2026-10-24 产品边界与轻量路线图

Tooku 定位收敛为自托管的 Navidrome 第三方网页播放器。Navidrome 继续拥有音乐库、扫描、收藏、歌单、元数据与转码；Tooku 保留播放与浏览界面、会话安全代理，以及轻量的账号偏好、队列快照和备份。后端保持单个 Node 进程与少量 SQLite，不建设微服务、云端账号、后台任务系统或第二套媒体管理层。

近期顺序调整为：先完成真实部署/浏览器/Docker 回归，再测量并优化首屏、登录、曲库和开始播放的加载与资源占用，然后补齐升级及错误恢复；发布稳定后才开发浏览器端拼音搜索和睡眠定时等直接播放工具。现有网络歌词与推荐按用户操作执行并停止扩张；同浏览器并行多服务器、服务器管理平台、实时跨设备、智能歌单、推荐画像、音频 DSP、离线歌曲和自动网络歌手资料不再列为近期任务。已有功能不在本次文档整理中删除，后续是否懒加载或增加部署开关以实际资源测量为依据。

本次只整理产品边界、README、Agent 约定、持久化说明和后续顺序，没有修改业务代码、依赖、数据库或运行服务；因此仅检查文档事实、链接范围和 Git diff，不刷新代码测试数字。

### 2026-10-24 稳定服务器身份与地址管理

代码提交：`539d3e5`（`feat: manage stable Navidrome server identities`）。

受管 Navidrome 在独立安全库 schema v2 中获得稳定随机 ID；初始地址作为加密 namespace 保持原 owner 算法，已有会话按需补齐 ID，不迁移或清空账号数据。完整服务器地址只存在 AES-256-GCM payload，SQLite 地址索引使用 SHA-256。登录后所有协议、封面和播放请求继续从当前会话读取固定上游，地址管理不会重建播放器或切换正在播放的流。

头像 → 账户与设置 → 账户新增“服务器地址”：可匿名验证同一 Navidrome 的新域名、端口或反向代理入口，再用当前会话凭据核对规范账号并明确确认合并；默认固定上游也可为此签发限定用途的短时票据。可从已验证地址中选择首选登录地址并更新本设备回填，或移除非当前会话地址；至少保留一个地址，旧地址移除后仍使用它的会话在下次请求时撤销。服务端已脱敏的地址管理错误可在设置中显示，普通用户数据 409 仍保持原冲突文案。

本次实际执行：Node 24.22.1 下 lint、typecheck、全量测试（48 个 Vitest 文件、505 项，另有 4 项 Node 原生测试）、build、容器配置不变量、服务端原生 TypeScript 导入和 diff 检查均通过；构建保留现有超过 500 kB 的分包提示（JavaScript 约 610.38 kB）。测试覆盖安全库 v1→v2、地址明文不落库、稳定 ID、票据确认、账号不一致、首选地址、当前地址/最后地址保护、旧会话撤销、客户端响应校验与错误脱敏；同时避开 Fetch 禁止端口，消除随机本地端口夹具的偶发失败。现有 18733 服务保持健康且未重启，因此运行中的后端仍是提交前版本。

边界：Navidrome 没有可依赖的全局实例 ID，地址合并依据当前账号验证和用户明确确认，只应用于同一服务的地址变化。单个 Tooku origin 仍只有一个会话 Cookie；并行多服务器和普通设置中的整台记录删除已在后续规划中移出近期范围。未使用真实账号合并地址，设置页布局、真实域名切换后的重新登录与播放由人工查看。

### 2026-10-24 受管音频 MIME 与 Chrome 实机回归

代码提交：`407bf32`（`fix: mask managed stream media types`）。

真实 Chrome 在已安装 AB Download Manager 扩展、恢复既有 HttpOnly 会话和真实 Navidrome 曲库后，旧响应会被扩展按 `audio/*` Content-Type 识别并显示下载入口。根据该扩展公开源码的[响应监听与媒体 MIME 判断](https://github.com/amir1376/ab-download-manager-browser-integration/blob/master/src/linkgrabber/DownloadLinkInterceptor.ts)及[无扩展名时的 MIME 回退](https://github.com/amir1376/ab-download-manager-browser-integration/blob/master/src/media/MediaOnTab.ts)，受管播放代理现在将上游媒体 Content-Type 统一改为 `application/octet-stream`，同时继续转发原始字节、Content-Length、单段 Range 与 Content-Range，不维护 IDM、NDM、ABDM 名称或 User-Agent 黑名单。自动化测试新增 MIME 断言；这一做法只减少依赖媒体 MIME 的自动探测，不阻止已授权用户保存可解码内容。

### 2026-10-23 响应式浏览、移动切歌与品牌细节

专辑、歌手和歌手详情中的列数控件现在按所在内容区宽度计算有效上限：控件显示实际列数，超过上限的选项不可选；内容区只能显示三列时控件直接禁用，避免看似可调却不生效。原来的 3/4/5/6/8 桌面偏好不被响应式覆盖，内容区重新变宽后自动恢复。

### 2026-10-23 固定上游真实地址持久化与正式音乐 API

修复填写默认 Navidrome 真实地址 `http://127.0.0.1:44533` 时被误判为外部直连、只能保存在当前浏览器的问题。登录和匿名检测先通过同源 `POST /api/tooku/connection` 判断地址是否匹配本部署的固定上游；匹配时统一改走 `/api/navidrome`，建立与 Tooku 根地址相同的服务器账号会话。服务端只比较规范地址并返回布尔值，不返回上游配置、不接受任意代理目标；登录前的请求不继承残留 Cookie 账号。旧 `/nd` 路径继续兼容，但不再决定是否支持持久化。

浏览器 `MusicApi.identity` 保留用户输入地址的旧规范值，会话的加密记录新增可选 `clientBase` 并在恢复时取回。因此以 `44533` 登录会继续读取此前该身份下的头像、设置、队列和历史，再沿用既有空服务器自动迁移、真实冲突预览、revision 和恢复前副本保护；没有清理或复制 localStorage/IndexedDB。旧加密会话没有 `clientBase` 时仍按原 `/nd` 身份恢复，数据格式和安全库 schema 不升级。推荐 API 密钥随固定上游账号统一保存在服务器，未匹配配置的其他地址仍只使用本机数据和会话草稿。

本次实际执行：lint、typecheck、全量测试（46 文件、483 项）、build、Node 24 原生 TypeScript 语法检查与 diff 检查通过。新增覆盖固定地址/loopback 别名识别、任意地址拒绝、直接地址 identity 保留、Cookie 恢复原地址、正式代理 GET/表单 POST/媒体/原生图片、旧 `/nd` 兼容和残留 Cookie 不接管新登录。当前 18733 服务保持运行，仅以匿名请求确认 `connection` 返回受管连接、`/api/navidrome/rest/ping.view` 到达 Navidrome 0.64.1；未提交真实账号、认证材料或用户数据写入。构建仍有已有超过 500 kB 分包提示（本次 JS 约 597.19 kB）。
