# 音乐推荐

更新：2026-10-22。包含样本覆盖、多样性与主页接入调整，不代表所有模型、平台目录和地区均已真实联调。

## 入口与行为

左栏“最近在听”下方为“为你推荐”，路由 `/recommendations`；主页“全部”展示带文字说明的简洁入口板块，可显示现有歌曲数量，不放歌曲明细、不请求平台链接。从头像进入设置，在“音乐推荐”中配置服务。推荐页与设置均可选择 10/20/30 首，默认 30。只有“生成推荐 / 换一批”才发起推荐，不自动生成；模型连接检测另发一次短请求。保留最近一批，失败或没有新候选时保留旧结果。平台链接核实独立进行，核实前可搜索歌曲。

推荐页保留一个主标题，数量、模式与更新时间合并为一行，不再重复“本次推荐”。未生成时显示“暂无推荐”和“从最近在听推荐新歌”。一首一行的文字表格沿用歌单字号与行距，歌名、歌手、专辑分列，另显示可信日期和时长，不放封面或占位图标；“时间”表头使用文字。歌曲/歌手/专辑/时间通过共享 `TrackColumnHandle` 调整，悬停列边界显示细线，拖动预览、放开保存，取消/卸载恢复，支持左右方向键与双击/Home 重置；复用既有账号列宽偏好，不新增存储字段。窄容器依次隐藏日期、专辑、独立歌手列，极窄时歌手归入标题下方。进入推荐页即核实整批歌曲链接，分组完成后立即更新相应行；点击歌曲或行内空白、右键、键盘激活标题均打开统一平台菜单，提供原生外部链接。未完成歌曲的菜单显示“正在核实歌曲链接…”并先给搜索入口，完成后原位更新直达链接；点击不另发请求，不下载图片。更新不抢焦点，已关闭或切到其他歌曲的菜单不会被迟到结果重新打开。移除“本库播放”，不操作 Tooku 音频。结果标明实际使用的算法/AI/混合模式；展开“收听参考”可查看将提交的样本。

当前范围不包含“不感兴趣 / 减少类似推荐”反馈，该功能已由用户明确暂缓。平台链接首次失败即提供搜索兜底，不增加重试入口；推荐封面抓取、本库播放和保证“小众”的承诺也不在当前实现范围。

开发与生产挂载同一套 handler，无新增依赖、进程或端口。共享歌曲比较规则位于 `src/domain/lyrics/matching.ts`，现支持通用目录元数据，既有歌词策略不变。

设置将算法模式显示为「Last.fm 推荐」，内部仍保留 `algorithm` 值以兼容旧配置与批次。「新歌手目标占比」表示优先安排未出现在本次收听样本中的歌手，实际占比受候选限制。Last.fm / AI 默认展开，Apple Music / Spotify 的可选连接配置默认折叠，均可收起，折叠不清除输入或检测结果；标题保留未检测/检测中/可用/失败的灰/黄/绿/红灯与可访问名称，详细结果继续就地显示。表单末尾显式保存，按钮不吸底浮动。Last.fm API Key 下不放提示小字，AI 仅说明填写 HTTPS 地址、模型名称与 Key，不展示厂商专属填写链接。Apple 商店与 Spotify 市场使用常用地区下拉；旧配置中不在常用列表的合法地区仍显示并保留，Apple 写小写、Spotify 写大写代码，不新增网络请求或存储结构。

## 样本与推荐

从最多 200 条有效收听记录中提取最近 30/40/50 首不同歌曲；仅分析时聚合，原始历史不变。重复次数的权重增益递减、总权重最多 5；时间权重以 14 天为半衰期。发送标题、歌手、专辑、可用时长、次数与权重；另向模型提供最多 90 首已推荐歌曲的标题/歌手用于避重。不发送账号、本库歌曲 ID、认证 URL、音频或歌词。

算法模式使用 Last.fm `track.getSimilar`：按歌手交错后尝试全部提交样本，每首最多 20 个候选；预算不足或网络失败会显示完成/未完成数量。对种子权重取平方根并封顶，合并相同候选时取最高关联分而非不断累加；按参考来源轮流保留候选，每位候选歌手最多三首，池最多 180 首。候选较少时，从陌生歌手候选中随机选择最多八首再查一层相似曲，仍保留原始收听来源，不把中间歌曲当成用户听过。即使中间曲目已推荐，也可作为扩展起点。查无歌曲或相似项为空视为正常空结果；认证、限流、网络等失败另行提示。Last.fm 业务码 4/10/26/29 与 HTTP 401/403/429 视为当批共享故障：取消尚未完成及后续请求、保留已完成候选，不重复查询 50 首；AI 阶段仍可继续。停止状态只限本批，下次手动生成可重新尝试，不形成永久禁用。

AI 模式与混合模式均可提名池外新歌，首轮最多为目标数的两倍、封顶 50 首；混合模式同时将最多 120 个均衡候选交给模型排序，使用临时短 ID，不允许替换已有元信息或生成 URL。提示综合全部种子、探索新歌手与非主打作品，并提供上一阶段的避重歌曲和每次不同的变化标识。提名必须经网易云、QQ 或已配置的 Apple Music 核实，按正式元信息重新计算 ID；无法核实的略过。可选 basedOn 只接受有效种子序号，依据标记为模型延伸。

核实、避重与多样性筛选后不足目标数时，最多追加两轮补充提名，提示中携带缺额 missing、当前已选 accepted、历史及本轮已尝试 avoid；补充不再重排原候选池，每轮建议缺额的两倍、至少 10 首、最多 50 首。相同提名不重复查目录，正式目录名也加入已尝试集合。首轮全部略过仍可继续补充，达到目标即停止；请求失败则结束，不自动重放该请求。已有结果保留，仍不足时明确显示实际数量和缺额，不虚构歌曲或放松多样性约束。

支持兼容 Chat Completions 的公网 HTTPS 接口：基址自动追加 `/chat/completions`，也可填完整地址；请求使用 `model`、`messages`、`temperature`、`max_tokens`。要求返回 JSON，兼容 Markdown JSON 代码块。不同模型的参数和响应能力需分别检测。

DeepSeek 官方根地址、`/v1` 与旧 `/chat/completions` 均经共享 `modelEndpoint` 统一为 `https://api.deepseek.com/v1/chat/completions`，设置推荐填写 `https://api.deepseek.com/v1`；其他兼容主机保留自己的前缀。检测与生成使用同一 transport、非流式响应、官方非思考模式和 JSON 输出格式，不自动改模型名。生成额度 8192 tokens，检测额度 1024 tokens，带 system/user 提示并核对 `{"ok":true}`；检测成功提示 JSON 输出正常。兼容文本 parts、BOM 和 JSON 代码块，分别识别空内容、截断、只有思考、拒绝、缺少 choices/message、无效内容 JSON、HTTP 非 JSON/代理拦截及认证/余额错误，不提取任意文本中的花括号或把思考当答案。有候选时仍可回退算法，不以歌曲数量判断 AI 成功。官方 JSON 模式也可能返回空内容，参见 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

模型独立 HTTPS Agent 同时采用 Node 默认和操作系统已信任的 CA，显式保持 `rejectUnauthorized: true`，保留域名校验、全部 DNS 结果公网检查和连接 IP 固定，不安装证书或修改系统信任。CA 在服务启动时读取，系统信任变化后需正常重启。本机无密钥检查复现过一个 DeepSeek 解析地址用默认 CA 报 `SELF_SIGNED_CERT_IN_CHAIN`，加入系统信任后两个地址均返回 401；修复后根地址、/v1 和完整地址也均返回 401。这只验证 TLS/路由，没有验证真实账户模型调用。

过滤当前样本和最近推荐过的最多 300 个 ID；再与近期最多 90 首的标题/歌手比对：规范化全半角、合作歌手顺序，收敛 Album/Original/Studio Version、Remaster 等已知同录音标记。仅对明确版本标记归一，不一律删除括号，现场、翻唱、混音、声学版、作品分部与未知附注保持区分。算法首层/扩展、AI 提名及目录改名后均检查，已有 ID 与存储格式不变。同一歌手（含合作歌手）、已知同名专辑最多一首；没有专辑元数据时不能推断专辑归属。默认新账号探索比例 70%，旧设置保留；先预留新歌手目标，再以关联分、参考来源覆盖和专辑惩罚贪心补足，每多选同一来源会降低后续优先级。算法模式对关联分轻微扰动，混合模式保留模型排序。宁可少推荐，也不放松歌手/专辑限制。没有客观流行度或完整音频风格数据，不能保证“小众”或精确相关性，也不显示伪造的热门度标签。Spotify 目录仅在推荐后用于链接核实，返回内容不输入模型。

## 平台与配置

| 服务 | 配置 | 用途 |
| --- | --- | --- |
| Last.fm | API Key | 相似歌曲；检测使用固定公开样本 |
| AI | 地址、模型名、API Key | 提名/排序；检测仅发送短提示 |
| 网易云 / QQ | 固定公开目录，无账号 Cookie | 版本匹配和歌曲链接 |
| Apple Music | 可选 Developer Token、商店地区（默认 cn） | 官方目录与歌曲 URL |
| Spotify | 可选 Client ID / Client Secret、市场地区（默认 US） | Client Credentials 临时令牌及官方搜索 URL |

Last.fm 填写 API key，不填写 Shared secret。各服务的检测按钮旁持续显示未检测、检测中、成功或失败原因；未填必需配置时就地提示，不发网络请求。只校验和发送所选服务的配置与凭据，并清理密钥首尾空白。修改对应字段会取消检测并清除旧状态，修改其他服务或保存相同设置保留结果。检测状态仅在当前设置页有效，不作为持续健康保证。

使用歌名、歌手（含来源别名）、专辑、时长、Live/翻唱等版本信息匹配。直达链接限定固定 HTTPS 平台主机和歌曲路径，拒绝任意 URL 和认证查询参数。未配置、限流、故障、无匹配时显示带“搜索”标记的入口。目录命中不保证该地区的播放权限。

日期、时长和专辑只使用已匹配目录元数据：网易云 publishTime、QQ time_public、Apple releaseDate、Spotify release_date 等现有搜索返回字段，不追加专辑详情查询，不让 AI 生成日期或时长。只到年的日期不补月日，无效/缺失显示“—”。AI 核实时仅从目录重建专辑/日期/时长，目录缺失则不保留提名里的猜测；已有数据随批次保存；算法歌曲在整批链接核实中补齐行内信息。多个平台元数据按配置顺序选择首个匹配版本，避免并发返回顺序决定显示内容。

## HTTP、凭据与限制

| POST 路径 | 输入 | 输出 |
| --- | --- | --- |
| `/api/recommendations/generate` | `settings, credentials, seeds, excluded, recentSongs?` | `RecommendationBatch` |
| `/api/recommendations/links` | `settings, credentials, songs` | 每首的链接及已匹配的专辑/发行日期/时长 |
| `/api/recommendations/check` | `settings, credentials, target` | 当次连接结果 |

输入最多 256 KB（覆盖多语言样本和有限避重元数据）、上游响应读取最多 1 MB；每 IP 每分钟生成/检测共 16 次、链接另计 60 次；全服务最多 4 个在途操作。Last.fm 并发 4，服务实例按至少 250 毫秒间隔发起请求；目录并发 4。Last.fm 单次预算 10 秒、整个阶段 60 秒；其他来源 6 秒、每轮模型 45 秒、每轮 AI 核实 35 秒。服务端生成总计 300 秒（含最多两轮补充）、检测 50 秒、链接 20 秒，客户端分别多留 5 秒。推荐页按六首一组、两组并发核实整批，分组返回即更新行及当前菜单；部分分组失败保留成功结果并为失败歌曲提供搜索入口，即使全部失败也返回搜索入口，不新增重试按钮，不自动重放当前失败查询。不会自动重试失败的生成请求；客户端断开或服务退出取消在途工作。查询按账号、整批歌曲版本、平台/地区、凭据代次复用五分钟缓存，切账号/配置和卸载取消在途请求；主页不触发链接请求。

密钥、Client Secret、Developer Token 仅会话/请求内存，Spotify 临时令牌可在服务进程内按有效期复用；不写 localStorage、IndexedDB、SQLite、备份、日志或前端查询 key。切换 MusicApi 会话时清除密钥，页面卸载取消工作，迟到结果不能写入其他账号。模型调用仅携带模型密钥，平台凭据仅发往对应固定主机；上游错误采用固定文案，不返回原始响应。

服务端不保存账号配置、原始密钥或个人生成批次。目录与 Spotify 令牌通过 `cache.ts` 在进程内受限复用：目录成功查询五分钟、正常空查询三十秒，最多 256 项，每项最多 32 KiB；令牌最多 16 项，按官方 `expires_in` 扣除请求耗时及最多三十秒余量，最长一小时，缺少/无效有效期不缓存。认证返回 401 时丢弃旧 Spotify 令牌供下次手动查询使用，本次不刷新重试。缓存 key 使用平台、标题/歌手、地区及相关凭据的 SHA-256 摘要，不存明文密钥；不同凭据和地区不共用授权目录结果。并发同项合并请求，一个调用方取消不影响其他调用方，全部离开或服务关闭才取消共享工作；全部调用方已取消的工作、异常和超大项不进入缓存，返回副本防调用方污染。缓存不进入 SQLite、备份或日志，服务关闭清空。此接口与网络歌词一样是同源限流服务，不依赖 Navidrome 会话认证，公开部署沿用外层访问控制。完整地址直连 Navidrome 时推荐仍可用，个性数据仅保存本机。

模型地址限定无用户名/密码/查询/片段的 HTTPS 默认端口。所有解析结果必须为公网地址，将验证 IP 固定到实际连接，拒绝私网、回环、保留地址和重定向，避免作为任意代理。

## 保存与兼容

账号文档 v1 的可选 `recommendations` 保存 settings、batch，以及可选 seenIds（最多 300 个 ID）、recentSongs（最多 90 首 ID/标题/歌手）。批次歌曲可包含经目录核实的可选 releaseDate，缺省仍可读；整批链接核实补齐的信息仅在查询缓存，不自动改写已保存批次。`settings.resultCount` 可选，旧配置缺省按 30；兼容旧 settings/batch 文档、10 首旧结果及无推荐字段的备份，不清空存储、不升级 SQLite schema。普通设置、最近结果和避重元数据随既有账号文档同步、备份和 revision 冲突处理；密钥不在白名单。模型地址不能夹带认证信息。平台返回的 URL、目录正文、封面与临时令牌不进入账号文档；平台查询结果仅缓存 5 分钟。

本机 `tooku-recommendations` 按旧 `api.identity` 保存回退，读取时验证。默认状态不创建空账号记录。旧文档/备份继续有效，明确恢复旧备份会重置当前账号推荐数据，保留其他账号。无 SQLite schema 或文档版本升级，不清空旧存储。保存失败时会话保留可见状态并提示核实同步或导出备份；同步/恢复不操作音频。
