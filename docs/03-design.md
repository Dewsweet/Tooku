# 交互与视觉设计

## 视觉方向

用户已确认产品名 Tooku，界面参考 Apple Music 的简洁白色风格。以白底、浅灰导航、细分隔线和红色强调为基线，封面与音乐内容优先，歌词页使用大字号和清晰留白。深色主题是可选项，默认浅色；封面背景动效留到后续体验实验。

不整页照搬参考播放器。首页避免没有真实数据的榜单、排行榜、推荐文案和大面积装饰。空音乐库应引导检查 Navidrome 扫描结果。

## 页面与导航

| 页面/路由建议 | 内容与主操作 |
| --- | --- |
| `/login` | 服务地址、用户名、密码、连接诊断；本机提示地址 44533 |
| `/` | 继续收听、最近添加、收藏专辑、库内随机选曲 |
| `/albums` / `/albums/:id` | 专辑封面网格；专辑详情、按碟曲目表、播放全部 |
| `/artists` / `/artists/:id` | 歌手列表、专辑、关联曲目；缺资料时保留基础信息 |
| `/search` | 搜索框、分类结果、版本信息；输入和返回位置可恢复 |
| `/favorites` | 歌曲/专辑/歌手切换 |
| `/playlists` / `/playlists/:id` | 普通歌单、创建/编辑、批量操作 |
| `/history` | 标注“此设备”的收听记录 |
| `/settings` | 外观、歌词、音质偏好、快捷键、缓存、连接信息 |

队列是可随时打开的侧栏/抽屉；全屏播放器是覆盖层，与页面路由和音频生命周期分离。关闭覆盖层回到原滚动位置。

## 桌面布局（≥ 1024px）

左导航约 216px；顶部搜索与页面动作；主区域自适应；底部播放器约 88px。队列侧栏约 340px，窄屏时覆盖内容而不是压缩成不可读表格。

曲目表包含标题、歌手、专辑、时长、收藏、更多菜单；格式和码率放在详情/提示中。点击标题查看详情，独立播放按钮立即播放；双击行可作增强操作，不能成为唯一入口。

全屏播放器左侧封面与曲目信息、右侧歌词；底部仍有明确播放控件。歌词内容多时保留手动滚动，提供“回到当前歌词”。

## 手机布局（360–767px）

底部导航 + 上方迷你播放器，考虑 safe-area；搜索页独立入口。内容至少留出两层固定栏高度，最后一行可点击。封面网格 2 列起步，长歌名最多 2 行。

点击迷你播放器展开全屏；歌词和封面可切换。队列为底部抽屉；触控目标至少 44×44px。调序提供“上移/下移”替代拖拽；普通歌单删除和整队列替换可撤销。

768–1023px 为紧凑侧栏/平板布局，保持相同操作语义。竖屏与横屏均检查。

## 播放与队列的可见语义

| 操作 | 结果 |
| --- | --- |
| 播放全部 | 按当前列表顺序替换队列，从首项开始；提供短时恢复旧队列入口 |
| 立即播放单曲 | 建立该曲的单项队列并播放，行为在按钮提示中明确 |
| 下一首播放 | 插入当前播放顺序的下一位置，连续插入按操作顺序排列 |
| 添加到队列 | 追加到尾部，不改当前声音和进度 |
| 随机播放 | 生成一次随机顺序；屏幕上的队列反映实际接下来顺序 |
| 切换随机 | 保留当前曲目；上一首优先按实际播放历史返回 |

收藏、歌单编辑和队列临时操作的反馈需区别：歌单保存有服务器结果；队列本机保存显示本机状态。

## 初始设计 token（原型可调整）

| 类别 | 建议 |
| --- | --- |
| 字体 | 系统中文字体栈；不依赖远程字体；正文 14–16px，歌词 24–40px |
| 浅色 | 背景 #FFFFFF、导航 #F8F8FA、正文 #222222、强调 #E94C60 |
| 深色 | 背景 #19191C、卡片 #232327、正文 #F3F3F5、强调 #FA687C |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px |
| 圆角 | 控件 8px、卡片 12px、抽屉 16px |
| 动效 | 常规 160–240ms；歌词单独按时钟驱动；减少动态效果时关闭位移和氛围动画 |

实际文本对比度必须检测；自动封面色不能直接作为所有文字的前景色。无封面采用统一占位，不显示破图。

## 当前主界面（2026-10-19）

主界面已改为全局头部和三个圆角面板：Logo/主页/搜索/头像在头部，曲库切换进入设置，左栏只保留分类入口和独立歌单树，右栏纵向展示可配置的封面/歌词/详情/队列。底栏上方不再有左侧大封面。首页是独立曲库概览，具体操作和人工验收见 [主页改版清单](11-home-refresh-and-checklist.md)。

## 上一轮主播放界面（2026-10-14）

登录后的主界面现采用歌单优先的工作区：左侧固定导航与独立滚动的文件夹歌单树，中间歌曲表格或专辑卡片，右侧播放详情/歌词。真实曲库选择器和账户/设置位于左上角；明暗模式、主题色与各库入口可配置。去除首页营销横幅和多余的小号标签。操作和当前存储边界见 [主界面说明](10-library-workspace.md)。

白色与红色强调延续 Apple Music 的视觉方向；交互采用常驻控制栏、可展开的完整播放器、独立队列抽屉和明确的当前播放状态。点击底栏封面或展开图标进入完整播放器；收起或 Esc 返回原页面，音乐持续播放。

桌面完整播放器分为封面/控制与歌词/队列两列。手机纵向排列，保留大封面与控制，下滚查看歌词或队列；底栏简化为歌曲、上一首/播放/下一首、进度和队列。歌词缺失使用安静的空状态，不生成虚假歌词。

动效绑定实际状态：播放时封面放大、暂停时收回，切歌时信息淡入，播放/暂停按钮切换过渡，确认收藏后心形反馈；队列滑入，完整播放器进出有短暂位移与淡入。进度拖动先预览，松开提交；支持键盘调整与剩余时长切换。减少动态效果时取消位移并使用直接定位，状态反馈仍可辨认。

## 状态与可访问性

每个数据页面都设计加载、空、错误、无权限状态；断网显示可重试提示，仍播放的已缓冲音频不主动中断。音频格式失败与网络失败使用不同解释。

键盘建议：空格播放/暂停，左右键短距跳转，Ctrl/Cmd+K 搜索，Esc 关闭覆盖层；焦点在输入框、输入法组合或进度滑块时按控件自身语义处理。快捷键支持设置关闭。

图标按钮都有中文 accessible name；弹窗限制并恢复焦点；拖动进度有键盘替代；歌词当前行不每帧播报给读屏。媒体信息、当前曲目和错误使用克制的 live region。

## 原型交付清单

M1 先提交带交互的五个页面状态：登录、首页、专辑详情、队列、全屏歌词。分别审阅浅/深色与手机布局，再扩展歌单和搜索。最终视觉以真实标题、缺封面、双语长行和空数据验证，不能只用短英文 mock 内容。
