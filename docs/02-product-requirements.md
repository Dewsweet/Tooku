# 产品需求（PRD）

> 历史需求基线：下文保留 2026-10-13 的需求和测量目标，不代表当前功能状态或全部待开发。现行范围与交互见 [AGENTS.md](../AGENTS.md)，当前实现和验证见 [开发记录](09-development-status.md)；后续用户确认优先，不依据旧 PRD 恢复已取消的交互。

版本：0.1；日期：2026-10-13；状态：建议基线，等待真实音乐库联调和原型反馈。

## 定位与目标用户

Tooku 是自托管音乐库的日常网页播放器，面向拥有 Navidrome / NAS 音乐库、习惯中文音乐软件交互的用户。桌面浏览器优先，同时保证手机浏览、选曲、播放和歌词可用。

目标：打开后快速继续听；在大音乐库中找到想听的版本；看清歌词并舒适控制播放。美观须服务这些流程：封面与内容有层次，常用操作容易发现，操作不会打断音乐。

## 首版场景

| 场景 | 用户路径 | 成功条件 |
| --- | --- | --- |
| 连接私人服务 | 输入地址与账号 → 验证 → 首页 | 显示连接结果；认证失败可修正；不泄漏凭据 |
| 听专辑 | 最近添加 → 专辑 → 播放全部 | 曲目顺序含碟号；切换页面持续播放 |
| 找中文歌曲 | 搜索 → 查看歌曲/专辑/歌手 → 播放 | 输入法组合期间不发半成品查询；结果可区分版本 |
| 临时安排听歌 | 下一首播放 → 查看队列 → 调序 | 不丢失当前位置，重复曲目行为一致 |
| 沉浸听歌 | 展开播放器 → 歌词 → 点击某行 | 歌词随进度同步；无歌词也能完整控制播放 |
| 整理收藏 | 收藏 → 添加歌单 → 回到收藏页 | 写入结果真实；失败显示并回滚 |
| 继续上次收听 | 重新打开 → 恢复队列 → 点击继续 | 恢复暂停状态与进度，不未经交互自动播放 |

## 功能优先级

P0 为首版发布必需；P1 为后续体验增强；P2 为需单独验证的探索。所有条目目前均未实现。

| ID | 优先级 | 功能 | 数据/依赖及验收边界 |
| --- | --- | --- | --- |
| AUTH-01 | P0 | 地址与账号登录、退出、连接诊断 | ping + 内存凭据；保留服务 base path；支持失败重试 |
| LIB-01 | P0 | 最近添加、专辑、歌手、曲目详情 | 分页浏览，多歌手与多碟信息不丢失 |
| SEARCH-01 | P0 | 中文/英文检索，歌曲/专辑/歌手分组 | search3；300ms 防抖，IME 结束后提交，取消旧请求 |
| PLAY-01 | P0 | 播放/暂停、上一首/下一首、进度、可用音量控制 | 真音频；格式不支持可走转码或显示原因 |
| QUEUE-01 | P0 | 替换队列、追加、下一首播放、调序、移除、循环、随机 | 稳定队列条目 ID；操作后可恢复；边界见播放器文档 |
| FAV-01 | P0 | 歌曲/专辑/歌手收藏 | star/unstar；按权限可用；失败回滚 |
| LIST-01 | P0 | 普通歌单创建、重命名、加曲、移除与调序 | create/updatePlaylist；失败不可显示“保存成功” |
| LYRIC-01 | P0 | 逐行/静态歌词、字号、滚动、歌词偏移 | 服务端能力不足时静态/无歌词降级，不依赖外网 |
| UX-01 | P0 | 简体中文、明暗主题、响应式、键盘操作 | 360px 起不溢出；输入框内不劫持播放快捷键 |
| RESTORE-01 | P0 | 本机队列、进度、偏好恢复 | 按服务与用户隔离；不保存带认证的音频 URL |
| HISTORY-01 | P0 | 本机收听历史与服务端收听提交 | 不将本机历史说成完整跨设备历史；去重上报 |
| CN-01 | P1 | 拼音/首字母与简繁辅助搜索 | 本地增量元数据索引；明确覆盖范围；不假设服务器支持 |
| LYRIC-02 | P1 | 双语、注音、逐词歌词 | songLyrics v2 + 数据存在；逐词有真实时间戳才显示 |
| LYRIC-03 | P1 | 用户 LRC/TTML 导入、替换、偏移记忆 | 先本机覆盖；默认不写服务器文件；导入需预览 |
| UX-02 | P1 | 睡眠定时、命令面板、队列批量操作 | 定时按截止时间校正；不能保证移动后台准点触发 |
| PWA-01 | P1 | 可安装、应用壳/元数据缓存 | 安全上下文；“可安装”不等于歌曲已离线 |
| SYNC-01 | P1 | 手动保存/恢复服务端队列 | 能力检测，冲突由用户选择，本机队列不被静默覆盖 |
| IMPORT-01 | P1 | 歌单导入/导出 | 用户文件优先；匹配预览、未匹配清单、确认后写入 |
| LYRIC-04 | P1 | 可选在线歌词 | 默认关闭；显示来源与匹配置信度，不发送认证信息 |
| AUDIO-01 | P2 | ReplayGain、EQ、Crossfade、无缝播放 | 分开技术实验，浏览器/转码/后台兼容性通过后开放 |
| OFFLINE-01 | P2 | 选定歌曲离线 | 配额、Range、权限撤销、清理与 Safari 淘汰策略必须通过 |
| RECOMMEND-01 | P2 | 库内相似推荐与规则歌单 | 基线可规则推荐；智能/声学能力需要另测适配器 |

## 中国用户体验设计

1. 简体中文默认，所有状态和错误使用自然中文；歌名与歌手保留原始标签，不自动“纠正”曲库。
2. 在服务端原文搜索上补充拼音、首字母、繁简转换与用户别名；多音字需词组词典/别名纠正。首版先保证中文搜索与输入法行为。
3. 支持原文/译文/注音分层显示，以及歌词字号、行间距、偏移与低动效。缺少译文不伪造翻译。
4. 普通歌单导入支持用户 CSV/JSON/M3U 文件；按标题、歌手、专辑、时长/版本多条件匹配。国内平台分享链接解析为后续提供方能力，禁止把音乐 URL 当作迁移内容。
5. 默认无外部字体/CDN/统计依赖；在线服务可关闭并设置超时。避免外网失败阻塞播放。
6. 网络/音质模式使用“原始”“兼容”“省流量”等词；实际输出取决于浏览器和服务端，不能将请求标签当作已确认音质。

## 范围与数据归属

首版不覆盖服务器管理、标签批量修改、平台账号登录、音源解锁、MV、评论社区、投屏、桌面悬浮歌词或原生客户端。

Navidrome 持有音乐、歌单、收藏与播放计数；客户端持有主题、别名、歌词覆盖、局部搜索索引和本机队列。中国平台匹配信息、注音和个性标签只是客户端增强数据，不能假装已写入 Navidrome。

## 质量目标（待测基线）

统一测量环境：记录机器/浏览器、曲库规模、格式、原始/转码、网络条件；目标不作为已达成的性能事实。

| 指标 | 首版目标 |
| --- | --- |
| 音频启动 | 本机服务、MP3 原始流、热连接，点击至 playing 的 p95 ≤ 2 秒，至少 30 次样本 |
| 搜索 | 1 万首样本库、同上网络，提交至结果 p95 ≤ 1 秒，不含输入防抖 |
| 队列操作 | 1,000 条队列，新增/调序视觉反馈 p95 ≤ 100ms |
| 页面与歌词 | 活跃页避免持续长任务；低性能设备可关闭模糊背景与动画 |
| 稳定性 | 30 分钟连续播放与反复路由切换，不重复播报、不产生第二路声音 |
| 可访问性 | 全核心流程可用键盘完成；焦点明确，颜色不是唯一状态提示 |

## 需要原型阶段确认的偏好

产品名已确认 Tooku，视觉采用 Apple Music 风格的简洁白色界面；用户授权先初始化本地 Git，并允许考虑 Docker 部署。是否发布开源、手机端权重、音乐库规模与常见格式尚未确认。当前按单人开发、桌面优先、双主题、1 万首性能样本规划；这些假设不阻碍 M0 联调。
