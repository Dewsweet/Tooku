# Tooku 独立歌词组件方案与实现

更新：2026-10-21。首版已实现；本文取代 2026-10-20 的实施前设计稿，记录实际接口、参数和维护边界。历史设计可从 Git 查看。

## 产品边界

- 歌词组件属于 Tooku，随既有 Node 服务在同一进程、端口启动。网络搜索、获取、匹配、缓存和检测不依赖 Navidrome 插件、能力或登录。
- Navidrome 仍是本地标签歌词的读取渠道，网页不直接读取服务器音频文件或相邻 LRC。音乐、收藏、歌单继续由 Navidrome 管理。
- 默认本地优先，明确缺失才自动联网；本地外语原文缺少中文仍算有效。读取超时、权限和协议错误不视为缺失。
- 来源入口只有本地、网易云、QQ 音乐；默认本地，明确缺失后按设置顺序使用有歌词的网络来源。指定平台不偷偷换源；相近版本直接采用合适候选，用户发现不符时再到“歌词设置 → 版本”修正。纯音乐、占位文本与最终无结果在播放器统一显示“该音乐没有歌词，请欣赏”，不要求先选择版本。
- 不生成翻译或时间戳，不拼接不同来源的译文，不写标签，不全库/整张专辑预取；未接入平台登录、逐字动画、指纹识别或音频下载。
- 沿用唯一 player、音频元素与 QueryClient；切来源、修正歌词、状态检测及账号恢复不改变当前音频与队列。

## 数据与时间

`LyricDocument` v1 包含 `source`、`recordId`、原文/译文/罗马音 `tracks` 和可选 `instrumental`。轨道保留 `text` 或结构化 `lines`、`lang` 与 `offsetMs`；原始输入留存，排版修正不改写它。正文空轨与明确纯音乐分别表达无歌词和纯音乐；错误单独抛出/返回。

显示兼容现有 `Lyrics` / `LyricLine`，每句有原文、可选毫秒 startMs、译文及罗马音数组，不按文本去重，保留多时间标签、副歌和相同时间戳的多句。静态歌词不会按歌曲长度伪造同步。

OpenSubsonic 正 offset 表示提前，适配时转换为负延迟。普通 LRC 的 `[offset:]` 也转换为提前语义。各轨源延迟在配对前归入各行 startMs，规范结果 offsetMs 为 0；旧全局 lyricDelay 与按歌/来源 delayMs 在显示/定位时叠加：

```text
显示时间 = 音频秒数 × 1000 − 全局延迟 − 当前来源用户延迟
定位秒数 = (规范原文 startMs + 全局延迟 + 当前来源用户延迟) / 1000
```

## 本地双语整理

先保留原始顺序，再处理 BOM、换行、元信息、实体和 LRC 多时间标签。结构化字段内部换行展开后保留同一时间点，先识别双语区块再排序，防止时间轴回绕被排序破坏。来源明确标记中文译文或罗马音时优先使用独立轨。Unicode 字母识别支持带重音拉丁字母、俄文、希腊文、阿拉伯文、泰文等；英语/法语等本来使用拉丁字母的语言标签不当成罗马音，静态多轨即使译文先返回也保留外语原文语义。

| 格式 | 自动规则 | 手动修正 |
| --- | --- | --- |
| 外语与中文隔连续空格 | 两侧文字证据支持外语/中文，保留原文内部英文空格 | 同一行双语，可指定分隔符 |
| `外语 / 中文` | 支持斜杠两侧零到多个空格及全角斜杠，两侧存在语言证据 | 同一行双语 |
| 原文后跟译文 | 稳定交替、语言证据与相容时间支持；静态也可识别稳定交替 | 交替双语 |
| 前半外语后半中文 | 有效行等长、语言证据与时间轴回绕/受限配对支持；静态等长区块也可识别 | 前后分段，可指定原文行数 |
| 独立语言轨 | 同时间优先，误差最多 300 ms，且不超过相邻不同时间点间隔的三分之一，一对一配对 | 保留原始轨，可更换来源 |

无法确定时保留原文；明确双语行可以独立整理，不因其他行格式不同而全部失效。日文纯汉字句在已有多条可靠双语分隔的上下文中继续配对，不将单语中文的所有斜杠自动拆为译文；不完整静态分段不机械挪行。未配对译文原样保留为独立行，未配对罗马音保留在原始文档，不冒充原文显示。纯音乐/无歌词占位以及只有署名、空时间提示的文档不作为歌词正文。

统一“歌词设置”面板的“显示”页提供自动识别/保留原文/原文与译文同行/原文与译文交替/原文在前译文在后、分隔符/边界、同步偏移、译文与罗马音开关；已移除歌词预览。弹窗圆角 12 px，标题固定，内容在内层滚动，不让滚动条顶到外层圆角。偏移以秒输入、0.1 秒步进，内部仍保存毫秒。规则绑定歌曲、来源与原始内容 hash；源变化后保留旧记录但不套用旧规则。“重置显示”只删除当前来源修正，不修改原歌词。重置与刷新同行，保存单独一行；输入框和选择框共用 44 px 主题表面与焦点边框，滚动层为边框留出空间，偏移使用一个整合的输入区域。

## 选择、匹配与播放界面

自动策略只在本地明确空、非纯音乐时查询网络。无本地正文则按来源优先顺序请求；一处失败可以尝试下一处。指定平台只查询该平台；人工绑定优先于搜索。关闭网络后不请求自动搜索或检测，保留已有个人选择以便重新开启。

无绑定时比较标题、歌手、专辑、时长与 Live/翻唱/伴奏/Remix/TV Size 等版本。标题相似度至少 0.8、歌手至少 0.65、无版本冲突，时长误差不超过“10 秒与曲长 5% 中较大者、最多 15 秒”时可自动采用；无时长时要求标题至少 0.95、歌手至少 0.9。标题括号译名参与兼容（如 `風になる (幻化成风)` 对应 `風になる`）；候选可带平台返回的 `artistAliases`，匹配时与原歌手名一起比较，界面仍只展示 `artists`。歌手名在比较前展开全角斜杠、顿号、分号、带空格斜杠等多人写法与括号/方括号别名，两侧采用同一规则；保留 AC/DC 一类无空格斜杠名称。不因整段演唱/制作人员字段较长而拒绝其中已匹配的歌手，但版本冲突仍排除。不再要求第一名明显领先第二名，按排序取有数据的合适候选，一次最多两首；这些阈值是启发式，不宣称完整匹配率。

“歌词设置 → 版本”先分别编辑歌曲标题与歌手，下方再选择平台并搜索，提交后将检索描述与关键词一同更新；可切平台、查看歌名/歌手/专辑/时长并绑定；不播放平台音频。“恢复推荐版本”删除当前平台人工绑定，重新使用该平台合适版本。仅“显示”页提供“刷新歌词”，绕过相应缓存但遵守限流，“版本”页不重复提供；不再提供四项三点菜单和两张独立设置卡片。

展开播放器的来源、歌词设置、全屏和收起图标位于同一标题行，无胶囊外框，以竖线分组，QQ 来源使用同色企鹅图标；右栏保留紧凑的同款图标。通过 Portal 复用歌词实例的工具栏，不新建播放/查询状态。播放器标题样式只作用于直接子标题，不污染内部设置弹窗；关闭设置后恢复触发按钮焦点。原文大字，已有译文位于下方，罗马音默认隐藏；整组高亮、点击按原文时间定位。展开页按可用宽高缩放封面、列间距与歌词字号，适配 1K / 2K / 4K 与浏览器缩放；歌词阅读区限制为最高 64dvh / 1160 px，当前组中心位于阅读区高度的 42%，侧栏与窄屏保持 50%。首尾留白按锚点分别计算，确保两端短句也能到达同步位置。两个视口独立滚动，手动浏览显示“同步”，闲置 5 秒恢复跟随；换行、字体、容器尺寸改变后重新测量，保留键盘、IME 与减少动态效果。

顶部与底栏共用 `FullscreenButton`：在用户点击时请求根节点原生全屏，底栏同时展开播放器；已有原生弹窗在全屏后重新提升到顶层，保留 DOM/React 状态。监听 `fullscreenchange` 同步 Esc/浏览器退出，失败提示、无 API 时禁用；全屏不接管音频，不保存为账号偏好。展开页右键复用当前歌曲更多选项菜单，不显示主页导航；内部设置弹窗的文本输入仍保留编辑菜单。

本地查询 key 包含 `api.identity` 与 track ID；网络协调再包含歌曲元数据、模式、绑定、来源顺序及刷新代次，正文 key 包含账号、provider、平台 ID 和刷新代次。匹配规则调整使用新的前端查询策略代次，避免沿用旧规则计算出的无歌词结果；平台原始搜索/正文缓存和个人绑定无需清空。切歌、切账号或切源取消过期前端请求，迟到结果不能覆盖新曲目；服务端共享任务使用独立的有界请求信号。

## HTTP 契约与限制

| 方法 | 路径 | 请求 / 返回 |
| --- | --- | --- |
| GET | `/api/lyrics/health`、`/status` | v1、服务 enabled、缓存模式、平台 search/lyrics 近期观测；不联网 |
| POST | `/api/lyrics/search` | `{ track: { title, artists, album?, durationMs? }, providers, refresh?, keyword? }` → v1 candidates/errors |
| POST | `/api/lyrics/fetch` | `{ provider, id, refresh? }` → v1 document/cached/stale |
| POST | `/api/lyrics/check` | `{ providers }` → 真实检测后的状态；30 秒内重复检测跳过 |

输入 provider 只允许 netease/qq，平台 ID 只允许受限字母数字；域名与路径由服务端固定。请求上限 8 KB、上游响应 512 KB，每 IP 每分钟最多 60 次操作；同 key 合并，待处理任务最多 100。平台串行，间隔至少 250 ms；请求包括排队预算为 6 秒，实际外部 fetch 为 5 秒。前端一次自动决策总预算 15 秒，最多两来源、每来源一次搜索及两首可信候选歌词。网易云检索词含汉字且候选歌手使用假名、韩文或拉丁字母、搜索未含别名时，在搜索原有 6 秒预算内最多补读两个固定 `/api/artist/:id`；只接受同一数字 ID 返回的译名/别名，不推断中文与日文人名。别名内存缓存最多 40 位、1 小时，补读失败保留搜索结果；搜索缓存使用 v2 key 重建，旧记录保留，无数据库结构或个人数据迁移。429 暂停该来源 60 秒，不进行后台无限重试。

JSON 返回独立错误类型 timeout/rate-limited/login-required/unavailable/protocol/disabled；HTTP 参数错误 400、过大 413、类型错误 415、跨源 403、限流 429、停用 503、上游故障 502。搜索可同时返回有效候选和某来源错误，不把超时/权限/协议变化当成“没歌词”。

播放器不再把网络来源失败显示为音乐播放出错：尝试完允许的来源后，无可展示正文统一使用简洁空态；服务真实失败保留在状态观测及查询结果中，仍可在设置检测。该空态不是对平台完整收录状况的断言。本地读取失败仍保留明确错误，不擅自当成缺失触发联网。

公开接口没有 Navidrome 身份要求，同源检查不是认证；不返回个人绑定、Cookie 或凭据，不接受任意 URL，不上传本地歌词全文。HTTP fetch 使用 credentials omit、固定 Referer、拒绝重定向。公开部署沿用外层访问控制与 HTTPS；本次没有增加另一套账号认证。

部署环境变量 `TOOKU_LYRICS_ENABLED=false` 可停用整个网络服务；设置开关只控制当前账号的请求策略。平台状态独立区分搜索和歌词，错误不输出原始响应或请求凭据。

## 缓存、持久化与迁移

- 公开平台文档与搜索结果保存到 `TOOKU_DATA_DIR/lyrics-cache.sqlite`，默认 `.local/data/lyrics-cache.sqlite`，独立 schema v1，不触及用户库。未知/损坏/不可写缓存降级内存，不删除数据库。
- 正文成功缓存 7 天、搜索成功 1 小时、明确无匹配/无歌词 6 小时；失败不写负缓存。过期有效正文先显示旧版，后台刷新每条最多每小时一次，下次读取采用更新；缓存命中不会更新联网观测。
- SQLite 按使用时间回收，最多约 5000 条 / 100 MB，单项 512 KB；内存降级最多 40 条。容量为应用逻辑限额，SQLite/WAL 文件实际大小可能更大。
- v1 账号文档新增可选 `lyrics: { enabled, order, tracks }`，包含按歌来源、平台绑定、各来源排版/hash/延迟/显示选项，最多 2000 首，仍受账号 12 MB 总限额与共享白名单约束，不落库凭据或认证 URL。
- `tooku-lyrics` localStorage 按 identity 保留本机回退；通过 `/nd` 的已验证账号复用现有 revision、IndexedDB sync、导出/恢复与冲突选择。直连其他 Navidrome 仍仅本地保存个人选择，网络查询照常独立可用。
- 没有歌词配置时不新增空字段占据旧同步基线。旧文档/备份省略字段仍有效；恢复旧备份重置当前账号歌词选择，保留其他账号。409/结果未知沿用停止写入、读回比较规则，不清空本地数据迁移。
- 来源存储仍兼容旧 `auto` / `network`，前者按本地优先解释，后者使用当前来源顺序中的首个平台；界面不再显示它们，新记录缺省写本地。读取旧数据不自动改写账号文档，无 SQLite / 文档版本升级。
- 用户备份及 tooku.sqlite 完整备份包含个人选择，不包含可重建平台缓存。恢复/同步不调用 player.attach、不重新加载音频。

## 状态与协议维护

设置提供网络开关、来源顺序/单来源、服务状态和“检测”。平台搜索与歌词分别显示未检测/可用/限流/需要登录/暂不可用/未验证；详情展示最近观测时间与耗时。最近成功和检查时间保存在服务内存，重启为未检测；观测超过 30 分钟过期。读取状态或命中缓存不触发外网请求、不标绿；空结果不足以证明能力正常，也不把单曲未收录认定为整个平台故障。

主动检测使用固定公开样本的搜索与歌词两项操作，不发送用户私人元数据。`node scripts/probe-lyrics.ts` 可独立运行，无需 Navidrome；只输出摘要，写入被忽略的 `.local/lyrics-probe.json`，不输出歌词正文。

## 验证边界

新增纯规则、适配器、缓存、独立 HTTP、状态、来源选择、迟到请求、双视图及账号兼容测试；既有播放器/同步测试继续覆盖播放连续性和冲突保护。自动测试使用合成歌词、固定脱敏响应与隔离数据库，不修改用户歌单、标签或正在使用的数据库。详细视觉、真实标签样本与不同歌曲的匹配结果交由人工查看，交付回复直接列查看项。
